# 添加助手界面

助手界面负责让人阅读运行过程、发起任务、回应确认或人工接力。它与能力声明是两件事：加一个聊天窗口不会自动开放按钮，声明动作也不会自动生成一个可用入口。

## 每个任务上下文只选一个主界面

浮窗适合需要保留完整页面的场景，侧栏适合持续工作区，内嵌界面适合页面中的一个任务，聊天组件则适合由宿主自己组织布局。选择哪种，主要看用户是否需要同时观察页面与其任务状态。

不要为了提供两个视觉位置，让两个界面共享同一个会话。它们会争用对话记录、待确认请求和焦点。确实需要并存时，应为每个界面分配独立任务或运行时，并在界面中说明边界。

## 页面存在后再挂载

界面读取与应用相同的注册表和 UI 控制器。在应用入口统一配置一次，再挂载界面：

```ts
const pling = createPling({
  agent: { config: { limits: { maxTurns: 10 } } },
});

pling.dock({ title: "页面助手" });
```

Vue、React、原生 JS 与 Vue 2 适配器只是把同一运行时接到不同的生命周期上。模型配置、确认通道和任务导航应留在应用入口，不要在每个视觉组件里各写一份。

## 入口需要明确

启动按钮要有可访问名称和清楚的开关状态。打开界面不应自动执行动作，也不应重发上一条提示。关闭界面是否需要销毁会话，应由产品决定；如果只是收起，历史与待确认状态应保留。

高风险确认应留在应用界面中，并保证用户能从页面找到它。助手关闭时，操作应保持待处理或被明确取消，不能因为界面不可见就被自动批准。

## 界面至少要展示什么

至少要有当前对话、空闲或处理中状态、工具失败，以及取消、重试和回应待确认操作所需的控制。最近操作可以展示动作、目标、结果码与证据，但不应把敏感真值或整页状态原样倒出来。
