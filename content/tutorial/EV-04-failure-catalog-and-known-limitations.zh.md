# 失败样本与已知限制

只记录成功演示，最快失去信任。这份目录记录仓库里能看见的失败类别，以及当前实现尚未解决的问题。

## 失败类别

| 类别 | 例子 | 说明 |
| --- | --- | --- |
| 缺少声明 | 模型调用从未注册的 id | 选择器猜测不是契约；重新描述并补上操作 |
| 动作不可用 | 记录锁定或区域隐藏 | 可见性与前置条件是运行时事实 |
| 参数不符 | 缺少必填字段或类型错误 | schema 必须窄且当前 |
| 成功判据失败 | 点击发生，记录没变 | 合成成功不是业务证据 |
| 确认拒绝 | 真人拒绝危险操作 | 同意必须阻止执行，而不是装饰界面 |
| 超时 / 页面中断 | 工具调用期间导航 | 结果未知；重试前重新观察 |
| 会话过期 / 撤销 | 委托 token 失效 | 在执行器前失败，而不是写入后 |
| 重放 | 同一 invoke id 到达两次 | 协议防护不等于业务幂等 |
| 审计失败 | 审计 sink 不可用 | 业务结果与审计完整性要分别报警 |
| 网关 / 模型失败 | 上游超时或限流 | 基础设施失败必须与页面失败分开 |

## 已知限制

- closed shadow root 与跨域 iframe 不投影。
- 旋转或 3D transform 的 frame 坐标覆盖不完整。
- 浏览器适配器不会把每个纯视觉控件自动变成能力。
- Surface 协议当前只实现 `describe` 与 `invoke`。
- 包内没有标准传输，也没有面向第三方实现的公共一致性套件。
- 参考委托存储不是生产数据库，SSE 不是事实来源。
- 限流与防重放默认是进程内状态；多实例需要共享适配器。
- 基准只覆盖有限夹具与模型，不证明通用效率或安全。
- 浏览器诊断可能包含敏感页面上下文，生产不能无条件开启。
- 页面契约无法阻止拥有完整浏览器控制的 Agent 点击 UI；后端控制仍不可少。

## 基准中的失败证据

早期基准暴露了真实任务与 harness 缺陷：任务没有给足业务数据，鼓励模型猜测；上次动作留下的筛选状态使审批作用于隐藏记录；长列表任务接近轮数上限。这些问题促成了更明确的文案、可行动的恢复提示和预注册轮数预算。后续报告保留这段历史，而不是假装第一版就能成功。

当前确认性运行的正式样本没有失败，不代表失败不会发生。运行只覆盖一个夹具、一个模型别名和 200 条正式用例，不包含网络分区、被攻陷租户或敌意外部 Agent。

## 报告新失败

记录页面夹具、能力 id、请求包络、预期结果、观察结果，以及是否发生副作用；注明包版本与诊断是否开启。移除 token、Cookie、客户数据和供应商密钥。若涉及危险动作，保留业务状态并停止重试，直到真人复核。

不要把失败业务结果静默改写成成功聊天回答。模型说“完成了”不是证据；声明的成功判据与业务状态才是。

可行动检查见 [排障](/zh/troubleshooting/)，披露边界见 [安全与信任中心](/zh/security/)。
