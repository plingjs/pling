## 出发点：同一张页面，补上页面表达不了的部分

案例07 已经能完成创建课程。它有一个边界：弹窗关闭后，表单区域和字段动作一起消失。用户如果离开再回来，助手看不到刚才的草稿。

案例06 在完全相同的页面上加一个目标。目标不复制字段，也不接管保存。它只回答四个问题：

- 这件事要达成什么；
- 哪些边界不能越过；
- 怎样才算完成；
- 弹窗关闭或路由变化后，为什么它还在。

## 具体实现：只加三行

页面和[案例07](/zh/examples/course-create-directives-vue3)完全相同。两者都停在课程库，弹窗是关闭的。助手必须先调用真实的 `new_course` 按钮，才能看到表单。

任务接入只有三行：

```ts
const pling = usePling();
const disposeGoal = pling.task.goal(courseGoal(props.locale));
onBeforeUnmount(disposeGoal);
```

`courseGoal()` 只写目标、约束和成功条件：

```ts
{
  id: "course.create",
  title: "创建课程",
  goal: "自己打开真实表单，按用户给出的信息填写，封面请用户上传，保存后回读课程库确认新课程在第一位。",
  constraints: ["页面动作是唯一入口", "封面必须由用户上传"],
  successCriteria: ["新课程出现在课程库第一位"],
}
```

这里没有 `fields`，没有 `steps`，没有 `controller`，也没有保存回调。字段来自真实页面，保存来自 `save_course`。

## 运行并验证

在仓库根目录执行：

```bash
pnpm dev:examples
```

打开 `http://127.0.0.1:5191/demos/course-workspace-vue3/?lang=zh`，依次试：

1. 页面应停在课程库，弹窗是关闭的。
2. 输入“创建孕妇瑜伽，陈静，2 星，月卡，介绍自动填写”，助手应启动目标，并自己点击“新建课程”。
3. 填完信息后关闭弹窗，再问“刚才那门课还差什么”。目标应仍然存在，助手可以重新打开表单。
4. 问“上传封面在哪里点”，助手应定位真实上传区，文件仍由你选择。
5. 保存后，`save_course` 应回读课程库，确认新课程在第一位。
6. 回读通过后，助手才调用 `pling_complete_task`，目标卡变为已完成。

## 最终效果

用户看到的是一个连续的任务：即使关掉弹窗，创建课程这件事还没有丢。助手可以重新打开表单、继续对话或请你补充封面。

页面没有多出第二张表单，也没有多出一条执行通道。目标只管理生命周期，页面动作仍然逐条经过原有的权限、确认和审计。

## 目标不做什么

- 它不打开弹窗。`new_course` 通过自己的点击处理打开。
- 它不读写字段。`course_name`、`course_teacher`、`course_cards` 等页面动作负责这些操作。
- 它不保存。`save_course` 调用页面自己的保存函数，并回读课程库。
- 它不放宽权限。每条动作仍然执行自己的风险、确认、作用域和审计规则。

模型多看到的唯一动作是 `pling_complete_task`。它在页面满足成功条件后关闭目标，不写业务数据。

## 为什么同一张页面有两个案例

案例07 是最短接入。一张稳定的单页表单就是全部工作时，用它。

案例06 是同一张页面加连续性。弹窗可能关闭、用户可能离开再回来，或外部 Agent 需要固定完成边界时，用它。

两个案例都没有增加第二张表单或第二条执行通道。
